# W6: World IDKit merchant verification (Opus)

**Own:** `apps/api/src/world.ts`, `apps/web/src/routes/onboard/**`, `docs/WORLD_DEBRIEF.md`.

Read PLAN.md section 2 "World IDKit" and `research/tracks/identity-privacy.md` (World section; read-only) and `research/tracks.md` (World "Best Use of IDKit" requirements: "Build a product that uses IDKit to solve a real trust moment... We are rewarding the best decision about which credential is needed, why it is needed, and how it improves a real product experience"; must show a denied/failure path; integration debrief required). Packages: `@worldcoin/idkit` 4.6.0 and `@worldcoin/idkit-core` 4.6.0; read their `.d.ts` in node_modules first (IDKit 4 has signed requests and an RP id; tutorials for v1/v2 are wrong).

- Trust moment: a merchant asks PaisaLink to sponsor gas for its customers. Credential: Proof of Human (one human, one sponsored gas budget; device-level is farmable; passport/selfie reveal more than needed). Write this reasoning into the UI copy and the debrief.
- API: `apps/api/src/world.ts` -> `export function worldRoutes(ctx: PluginContext): Hono` (see `apps/api/src/plugins.ts`, `docs/handoffs.md`): `POST /world/verify` verifies the proof server-side (IDKit 4 server verification / signing key from `@worldcoin/idkit-core/signing`), action `paisalink-merchant`, signal = merchant wallet, checks the nullifier is new (store nullifiers in `.data/nullifiers.json`, git-ignored, never on Arkiv), then `ctx.store.setMerchantVerified(wallet, true)` and `ctx.notify`. Reused nullifier -> 409 `NULLIFIER_REUSED`. Any IDKit request-signing endpoint the v4 flow needs (e.g. `GET /world/request`) also goes here.
- Web: `apps/web/src/routes/onboard/index.tsx` (`/onboard?wallet=0x..`): explain why verification is needed in one sentence, IDKit widget (staging, simulator `https://simulator.worldcoin.org/id/0x18310f83`), success -> badge "Verified human: gas-sponsored checkout on"; cancel/fail -> "Gas-sponsored checkout locked: verification not completed" plus the self-paid fallback path. Reuse W3's `src/lib/*` and `src/components/*` (see "W3 -> W5 / W6" in `docs/handoffs.md`).
- Env: `WORLD_APP_ID`, `WORLD_RP_ID`, `WORLD_SIGNING_KEY`, `WORLD_ACTION`, `VITE_WORLD_APP_ID` in root `.env.local`. They may still be EMPTY (the human is creating the Developer Portal app). Build and unit-test everything now; when they are empty, the API returns 503 `WORLD_NOT_CONFIGURED` and the page says so. Re-run `bash scripts/load-env.sh` to pick up values once they exist, and then do one real simulator verification end to end (report the result).
- `docs/WORLD_DEBRIEF.md`: time to first success, friction, missing capability, one improvement (World asks for this). Keep a running log of what you hit.
- Tests: proof-verification wrapper with a test double for the World verify call (test files only), nullifier reuse, denied path.
