## Design changes vs PLAN.md (coordinator decisions, so merchants never need gas: "payments nobody notices")
- PaymentRouter gets an `operator` (the relayer `0x645b…DA8F`, settable by owner). Add `createInvoiceFor(bytes32 invoiceId, address merchant, uint256 amount, uint64 dueAt)` callable by the operator, besides merchant-direct `createInvoice`.
- Add signature paths so the relayer can submit on the merchant's behalf: `refundWithSig(invoiceId, amount, deadline, sig)` and `withdrawWithSig(invoiceId, deadline, sig)`, verified on chain with EIP-712 (OpenZeppelin `EIP712` + `SignatureChecker`), with per-merchant nonces. Keep the direct `refund`/`withdraw` too.
- `payWithAuthorization(...)` calls USDT `receiveWithAuthorization` with `to = address(this)` and `value == invoice.amount`; event `InvoicePaid(invoiceId, payer, amount, gasless=true)`. `pay()` (transferFrom) is the self-paid path with `gasless=false`.
- InvoiceNote (Tokenize): one contract, many notes; owner-managed investor allowlist; `issue` by the merchant (or `issueWithSig` via relayer), `fund` by an allowlisted investor (USDT to the issuer), transfer only between allowlisted addresses and only before maturity, `settle` on/after maturity pays face value in USDT to the holder. Design how settlement is funded so it is enforced (for example: when a financed invoice is paid, PaymentRouter routes the face value into InvoiceNote escrow for that note, or the issuer pre-approves with USDT `permit`). Choose the simplest design that is enforced on chain, document it in `docs/specs/contracts.md`, and test it. Support a short maturity (e.g. 120 s) for the demo.
- Use OpenZeppelin v5 (`SafeERC20`, `ReentrancyGuard`, `Ownable`, `EIP712`) via `forge install` (pin a tag), forge-std for tests.
